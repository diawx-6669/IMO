# IMO Workbench

Статический сайт для подготовки к Международной математической олимпиаде: банк реальных задач IMO
1959–2025 с подсказками и разборами, маршрут подготовки, тренировочные туры по регламенту олимпиады,
библиотека техник и учёт прогресса по семибалльной шкале. Интерфейс на четырёх языках, материалы —
на русском и английском.

Открывается двойным кликом по `index.html` — ни сборки, ни сервера, ни зависимостей из сети не нужно.

## Что внутри

**Тест** — диагностика из двух частей. Первая проверяется автоматически: шестнадцать условий,
по четыре из каждого раздела, к каждому нужно выбрать приём, который его открывает (решать не надо,
около 15 минут). Вторая, по желанию, — четыре задачи на 80 минут с самооценкой. На выходе: уровень,
индекс 0–100, профиль по разделам и модуль маршрута, с которого стоит начать. Слабый раздел из теста
двигается вперёд в рекомендациях плана.

**План** — страница, с которой начинают: что делать прямо сейчас (рекомендация пересчитывается по
вашему прогрессу), как устроена тренировка, честный разбор того, как попадают на IMO, куда идти за
дополнительными материалами, и маршрут из трёх ступеней и 14 модулей, покрывающих все 82 задачи.
Модуль считается пройденным, когда по каждой его задаче есть балл 5 и выше.

**Задачи** — 82 задачи, отобранные по всем годам и разделам (A — алгебра, C — комбинаторика,
G — геометрия, N — теория чисел). Фильтры по разделу, по месту в наборе (1·4 — разогрев, 2·5 — средняя,
3·6 — трудная), по статусу и полнотекстовый поиск. В карточке задачи: формулировка, таймер,
2–3 подсказки, раскрываемые по одной, ответ, разбор, самооценка 0–7 и личные заметки.

**Тренировка** — генератор тура по структуре настоящего дня олимпиады: три задачи (по одной каждого
уровня), 4 часа 30 минут, максимум 21 балл. Есть короткий вариант на 1:30. Приоритет отдаётся задачам,
которые вы ещё не решили. История туров сохраняется.

**Арсенал** — 38 приёмов: что утверждает техника, по каким признакам её узнать, где обычно теряют
баллы и на каких задачах банка она отрабатывается (ссылки ведут прямо в задачу).

**Прогресс** — набранные баллы по разделам и по уровням сложности, распределение оценок, серия дней
подряд, время за доской, ориентир по медальным порогам, экспорт и импорт данных, и очередь
интервальных повторений: задача с баллом ≤ 3 возвращается через три дня, с баллом 4 — через неделю,
с 5–6 — через три недели.

**Рейтинг** — общая таблица класса: место, баллы, серия дней подряд, решённые задачи и последняя
активность. Сортировка по баллам, по серии или по решённым; своя строка подсвечена. Баллы считаются
с поправкой на сложность: задачи 1 и 4 с коэффициентом 1, задачи 2 и 5 — с коэффициентом 2,
задачи 3 и 6 — с коэффициентом 3, так что максимум за одну задачу — 21.

**Профиль** — вход в рейтинг: ученик вписывает имя, и его показатели начинают уходить в общую
таблицу при каждой новой оценке. Там же кнопка выхода из рейтинга (строка удаляется, прогресс
в браузере остаётся) и панель «Для учителя», которую видит только владелец страницы: сколько
учеников зарегистрировалось, сколько активны за неделю, сумма и медиана баллов, список с датами
регистрации и последней активности, выгрузка в CSV.

**Языки** — интерфейс на русском, английском, украинском и испанском; язык определяется по браузеру
и переключается в шапке. Условия, подсказки и разборы есть на русском и английском (английский —
официальный язык IMO); при украинском и испанском интерфейсе материалы показываются по-английски,
о чём прямо сказано в карточке задачи.

Горячие клавиши: `/` поиск, `J`/`K` вперёд-назад, `H` следующая подсказка, `S` разбор, `T` таймер,
`R` случайная задача, `0`–`7` поставить балл.

## Честно о данных

* Формулировки **переведены на русский и набраны вручную** по памяти составителя банка. Они близки к
  оригиналу, но это не официальный текст. В карточке каждой задачи есть ссылки на
  [imo-official.org](https://www.imo-official.org/problems.aspx) и на вики AoPS — сверяйтесь с ними,
  прежде чем считать условие точным. Задачи, где уверенность в формулировке ниже (IMO 2025),
  помечены плашкой «сверьте формулировку».
* 14 разборов из 82 — **наброски**: ключевые идеи и схема без полного оформления. Такие помечены
  плашкой «разбор — набросок» и предупреждением в начале разбора. Остальные 68 доведены до конца.
* Ответы к задачам 1960/1, 1981/3, 2006/3, 2011/1, 2015/2, 2019/4, 2022/5, 2023/1, 2025/4 дополнительно
  проверены перебором (`tools/`), для 2001/6 перебором проверено ключевое тождество.
* Шкала 0–7 — настоящая шкала IMO (42 балла за два дня), но рубрика в интерфейсе **ваша собственная**:
  официальные схемы оценивания индивидуальны для каждой задачи.
* Медальные пороги в разделе «Прогресс» — усреднённый ориентир; реальные меняются каждый год.
* Раздел «Как вообще попадают на IMO» описывает общую схему отбора. Регламент в каждой стране свой
  и меняется — проверяйте его у организатора олимпиады в вашей стране.

## Рейтинг: три режима хранения

Сам сайт статический, поэтому общий рейтинг требует, чтобы данные где-то лежали. Код выбирает
режим сам, порядок такой:

1. **Артефакт claude.ai.** Страница опубликована артефактом — используется база данных самого
   артефакта. Отдельно поднимать ничего не нужно. Ограничение платформы: писать в общие документы
   могут владелец и те, кому артефакт выдан хотя бы как Contributor. Зритель с доступом «только
   чтение» увидит рейтинг, но его результаты туда не попадут — страница говорит об этом прямо.
2. **Свой сервер.** В `data/backend.js` указан адрес — рейтинг идёт через него. Работает для любого
   числа учеников по обычной ссылке. Готовых реализации две: `server/cloudflare/` (Cloudflare
   Workers + D1, бесплатно) и `server/server.js` (обычный Node без зависимостей, пишет в файл).
   API у них одинаковый. Инструкция и честный разбор модели доступа — в `server/README.md`.
3. **Локально.** Ни того, ни другого нет: профиль и «рейтинг из одного человека» живут
   в `localStorage` этого браузера. Тренироваться это не мешает, но сравнить себя не с кем.

Показатели присылает клиент, то есть ученик с консолью разработчика может отправить себе любые
числа. Для класса это приемлемо; рейтингом, которому можно доверять на отборе, он не является.

## Как захостить

**Сайт.** Он статический, собирать нечего. GitHub Pages: Settings → Pages → Source: *Deploy from a
branch* → `main`, папка `/ (root)`. Через минуту сайт будет на
`https://<логин>.github.io/<репозиторий>/`. Подойдёт любой статический хостинг или просто
`python3 -m http.server` в папке репозитория.

**Общий рейтинг.** Если он нужен, поднимите бэкенд по `server/README.md` (четыре команды для
Cloudflare) и впишите его адрес в `data/backend.js`. Без этого сайт работает полностью, кроме
общего рейтинга: он останется локальным.

## Структура

```
index.html               страница целиком
assets/app.css           стили (светлая и тёмная темы)
assets/app.js            вся логика: фильтры, таймеры, туры, план, повторения, прогресс, рейтинг
assets/cloud.js          профиль и общий рейтинг: артефакт claude.ai / свой сервер / локально
data/backend.js          адрес своего сервера (пусто — локальный режим)
server/cloudflare/       бэкенд рейтинга на Cloudflare Workers + D1 (бесплатно)
server/server.js         тот же бэкенд как обычный Node-процесс, пишет в JSON-файл
assets/vendor/katex/     KaTeX 0.16.9 (MIT), подключён локально — работает офлайн
data/lang/*.js           интерфейс: ru, en, uk, es (по 295 строк в каждом)
data/problems-1..5.js    банк задач по эпохам (русский — базовый язык данных)
data/en/problems-1..5.js английские условия, подсказки и разборы
data/en/techniques.js    английский арсенал
data/techniques.js       арсенал приёмов
data/plan.js             маршрут: ступени, модули, связи «модуль → техники → задачи»
data/diagnostic.js       вопросы диагностики (верный ответ сверяется с арсеналом)
tools/validate.cjs       проверка данных: разбор всех формул, переводы, маршрут, диагностика
tools/build-artifact.cjs сборка одного самодостаточного HTML
```

### Как добавить язык интерфейса

Скопируйте `data/lang/en.js`, переведите 295 строк, подключите файл в `index.html` — язык сам появится
в переключателе. Если материалы на этом языке тоже есть, поставьте `content: true` и добавьте
`window.IMO_L10N.<код>` по образцу `data/en/`. `node tools/validate.cjs` проверит, что ни один ключ
не потерян.

## Разработка

```bash
node tools/validate.cjs        # проверяет 4000+ формул через KaTeX и целостность данных
node tools/build-artifact.cjs  # собирает dist/imo-workbench.html одним файлом
python3 -m http.server 8000    # локальный просмотр
```

Прогресс хранится в `localStorage` этого браузера: он не уходит на сервер, но и не синхронизируется
между устройствами. Переносится через «Скопировать прогресс» / «Вставить прогресс».

### Как добавить задачу

Допишите объект в подходящий `data/problems-*.js` и запустите `node tools/validate.cjs`:

```js
{
  id: "2016-1", year: 2016, num: 1, topic: "G", tier: 1,
  title: "Короткое название",
  statement: String.raw`Текст с формулами $a^2+b^2$ и выключными $$\int_0^1 f$$`,
  answer: String.raw`…`,            // необязательно
  hints: [String.raw`…`, String.raw`…`],
  solution: String.raw`*Шаг 1.* …`, // *курсив* — подзаголовок шага
  tags: ["техника", "идея"],
  partial: true,                     // если разбор — набросок
  verify: true                       // если формулировку стоит сверить
}
```

Все текстовые поля пишутся через `String.raw`, иначе `\frac` превратится в управляющий символ.
Английский перевод кладётся в `data/en/problems-*.js` под тем же `id`. Новую задачу нужно также
добавить в один из модулей `data/plan.js` — валидатор требует, чтобы маршрут покрывал весь банк.

## Оформление

Палитра разделов (A/C/G/N) подобрана не на глаз: четыре цвета проходят валидатор цветовых схем
(полоса светлоты, минимум цветности, различимость соседних пар при протанопии и дейтеранопии,
контраст к фону) отдельно для светлой и тёмной темы. Семибалльная шкала IMO вынесена в сквозной
мотив — семисегментный индикатор рядом с каждой задачей. Шрифты: Literata для условий и заголовков
(она стоит рядом со шрифтом формул KaTeX), IBM Plex Sans для интерфейса, IBM Plex Mono для всех цифр.
Движение сведено к переходам 160 мс и отключается при `prefers-reduced-motion`.
