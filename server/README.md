# Где захостить и как включить общий рейтинг

Сайт статический: собирать нечего, достаточно отдать папку репозитория как
есть. Общий рейтинг — единственное, чему нужно место для данных.

Три способа, от самого простого:

| способ | сайт | общий рейтинг | что требуется |
|---|---|---|---|
| **Cloudflare Pages** | да | да, на том же адресе | только браузер, терминал не нужен |
| GitHub Pages | да | нет (рейтинг локальный) | три клика |
| GitHub Pages + отдельный Worker | да | да | немного терминала |
| свой VPS | да | да | сервер и домен |

---

## Способ 1: Cloudflare Pages — сайт и рейтинг в одном месте

Бесплатно, без терминала, деплой обновляется сам при каждом пуше в `main`.
Названия пунктов в панели Cloudflare иногда меняются, так что ориентируйтесь
на смысл, а не на буквальное совпадение.

**1. Подключить репозиторий.**
[dash.cloudflare.com](https://dash.cloudflare.com) → **Workers & Pages** →
**Create** → вкладка **Pages** → **Connect to Git** → выбрать репозиторий.
Настройки сборки:

* Framework preset — **None**
* Build command — пусто
* Build output directory — `/`

**Save and Deploy**. Через минуту сайт уже открывается по адресу вида
`https://имя-проекта.pages.dev`. Рейтинг пока локальный — осталось дать ему базу.

**2. Создать базу.**
В меню слева **Storage & Databases** → **D1** → **Create** → имя `imo-rating`.
Открыть созданную базу → вкладка **Console** → вставить туда целиком
содержимое [`server/cloudflare/schema.sql`](cloudflare/schema.sql) → выполнить.

**3. Привязать базу к сайту.**
**Workers & Pages** → ваш проект → **Settings** → **Bindings** (в части версий
панели это **Functions → D1 database bindings**) → **Add** → D1 database:

* Variable name — `DB` (ровно так, тремя буквами)
* D1 database — `imo-rating`

Сохранить.

**4. Передеплоить, чтобы привязка подхватилась.**
Вкладка **Deployments** → у последнего деплоя меню **⋯** → **Retry deployment**.
(Любой следующий пуш в `main` сделает то же самое.)

Готово. Откройте `https://имя-проекта.pages.dev`, зайдите в «Профиль»,
зарегистрируйтесь — и в «Рейтинге» появится строка, которую увидят все.

`data/backend.js` трогать не нужно: сайт сам находит рейтинг на своём домене.

**Необязательно:** ключ для `GET /api/admin`. **Settings** →
**Variables and Secrets** → добавить секрет `ADMIN_KEY`. Панель «Для учителя»
в самом сайте работает и без него.

### Лимиты бесплатного тарифа

На октябрь 2026: 100 000 запросов в день у Functions, 5 млн чтений и
100 000 записей в день у D1, база до 5 ГБ, 500 сборок в месяц. Класс из
тридцати человек не приблизится: строка рейтинга — пара сотен байт, а запись
происходит не чаще раза в полторы секунды на ученика.

## Способ 2: GitHub Pages — только сайт

Settings репозитория → **Pages** → Source: **Deploy from a branch** → ветка
`main`, папка `/ (root)` → Save. Через минуту сайт на
`https://<логин>.github.io/<репозиторий>/`.

Работает всё, кроме общего рейтинга: профиль и рейтинг останутся
в `localStorage` каждого браузера, и сайт прямо об этом пишет.

## Способ 3: GitHub Pages + отдельный Worker

Если сайт уже на GitHub Pages, а рейтинг всё же нужен, разверните
бэкенд отдельным воркером — здесь уже нужен терминал:

```sh
cd server/cloudflare
npx wrangler login
npx wrangler d1 create imo-rating       # выведет database_id
```

Впишите `database_id` в `wrangler.toml`, а в `ORIGIN` — адрес сайта
(например `https://логин.github.io`). Дальше:

```sh
npx wrangler d1 execute imo-rating --remote --file=schema.sql
npx wrangler deploy
```

Команда напечатает адрес `https://imo-rating.<поддомен>.workers.dev`. Его —
в `data/backend.js` в корне репозитория:

```js
window.IMO_BACKEND = { url: "https://imo-rating.ваш-поддомен.workers.dev" };
```

Закоммитить, запушить. Ключ админа: `npx wrangler secret put ADMIN_KEY`,
логи: `npx wrangler tail`.

## Способ 4: свой сервер

`server/server.js` — тот же API обычным Node-процессом, данные в JSON-файле.

```sh
node server/server.js
```

| переменная  | по умолчанию           | зачем                                  |
|-------------|------------------------|----------------------------------------|
| `PORT`      | `8787`                 | порт                                   |
| `DATA`      | `server/students.json` | файл с данными                         |
| `ADMIN_KEY` | — (выключено)          | ключ для `/api/admin`                  |
| `ORIGIN`    | `*`                    | значение `Access-Control-Allow-Origin` |

Зависимостей нет, нужен Node 18+. Поставьте перед ним обратный прокси с
HTTPS (nginx, Caddy): браузер не пустит запросы с `https://`-страницы на
`http://`-сервер.

**Бесплатные PaaS сюда не годятся.** На free-тарифах Render и Railway диск
не сохраняется между перезапусками, а Render вдобавок усыпляет сервис через
15 минут без запросов — список учеников обнулится. Этот файл для VPS с
постоянным диском или для локальной сети; если нужно бесплатно, берите
способ 1.

## Эндпоинты (одинаковые у всех вариантов)

- `GET /api/board` — `{count, rows:[…]}`, публичный рейтинг без токенов.
- `POST /api/save` — тело `{token?, nick?, stats?, remove?}`; при первом
  вызове сервер выдаёт `token`, дальше клиент присылает его обратно.
- `GET /api/admin?key=…` — полный список по времени регистрации
  (работает, только если задан `ADMIN_KEY`).

Сколько учеников зарегистрировалось, видно тремя способами: в разделе
«Профиль» у владельца страницы, через `GET /api/admin` и прямо в хранилище
(консоль D1 в панели Cloudflare или файл `DATA`).

## Файлы

```
functions/_rating.js        вся логика: один модуль на все варианты
functions/api/[[path]].js   вход для Cloudflare Pages
server/cloudflare/          отдельный Worker: worker.js, wrangler.toml, schema.sql
server/server.js            тот же API обычным Node-процессом
```

## Честно о безопасности

Токен, который сервер выдаёт при регистрации, — одновременно и логин,
и пароль ученика; он лежит в `localStorage` браузера. Этого достаточно,
чтобы никто не переписал чужую строку, но это **не настоящая
аутентификация**:

- очистил браузер — потерял строку (придётся зарегистрироваться заново);
- общий компьютер — общий токен;
- показатели присылает клиент, поэтому ученик с консолью разработчика
  может отправить себе любые баллы. Сервер только ограничивает их сверху
  разумными значениями.

Для школьного рейтинга это нормально. Если нужен рейтинг, которому можно
доверять на отборе, оценки должен ставить не клиент, а проверяющий —
такого режима здесь нет.

Персональных данных не хранит ни один вариант: только имя, которое ученик
вписал сам, и числа.
