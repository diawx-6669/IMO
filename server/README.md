# Сервер для входа и общего рейтинга

Статическому сайту сервер не нужен: без него профиль и рейтинг работают
в локальном режиме — только в браузере ученика. Сервер нужен, когда вы
хотите **один общий рейтинг на класс** по обычной ссылке.

(В опубликованном артефакте claude.ai общий рейтинг работает без сервера —
через базу данных самого артефакта, но писать в неё могут только те, кому
артефакт выдан как Contributor. См. корневой README.)

Два варианта, оба с одинаковым API:

* **`cloudflare/`** — Cloudflare Workers + D1. Бесплатно, не засыпает,
  данные не теряются. Рекомендуется.
* **`server.js`** — обычный Node-процесс, пишет в JSON-файл. Для своего
  VPS или локальной сети.

---

## Вариант 1: Cloudflare Workers + D1 (рекомендуется)

Нужен бесплатный аккаунт на [dash.cloudflare.com](https://dash.cloudflare.com)
и Node на вашем компьютере. Всё остальное — четыре команды.

```sh
cd server/cloudflare

npx wrangler login                      # откроет браузер, один раз
npx wrangler d1 create imo-rating       # выведет database_id — скопируйте его
```

Впишите этот `database_id` в `wrangler.toml` вместо `ЗАМЕНИТЕ-НА-СВОЙ-ID`,
а в `ORIGIN` — адрес своего сайта (например
`https://ваш-логин.github.io`; можно оставить `"*"`, тогда запросы примутся
откуда угодно). Дальше:

```sh
npx wrangler d1 execute imo-rating --remote --file=schema.sql   # создать таблицу
npx wrangler deploy                                             # выкатить
```

Последняя команда напечатает адрес вида
`https://imo-rating.<ваш-поддомен>.workers.dev`. Впишите его в
`data/backend.js` в корне репозитория:

```js
window.IMO_BACKEND = { url: "https://imo-rating.ваш-поддомен.workers.dev" };
```

Закоммитьте, запушьте — и общий рейтинг заработает у всех по ссылке.

Ключ для `/api/admin` (необязательно, панель «Для учителя» в самом сайте
и так показывает всё):

```sh
npx wrangler secret put ADMIN_KEY
```

Посмотреть логи: `npx wrangler tail`.

**Лимиты бесплатного тарифа** (октябрь 2026): 100 000 запросов в день
у Workers, 5 млн чтений и 100 000 записей в день у D1, база до 5 ГБ.
Класс из тридцати человек не приблизится к этим числам: одна строка
рейтинга — это пара сотен байт, а запись происходит не чаще раза в
полторы секунды на ученика.

## Вариант 2: свой Node-сервер

```sh
node server/server.js
```

| переменная  | по умолчанию           | зачем                                       |
|-------------|------------------------|---------------------------------------------|
| `PORT`      | `8787`                 | порт                                        |
| `DATA`      | `server/students.json` | файл с данными                              |
| `ADMIN_KEY` | — (выключено)          | ключ для `/api/admin`                       |
| `ORIGIN`    | `*`                    | значение `Access-Control-Allow-Origin`      |

Пример:

```sh
PORT=8787 \
DATA=/var/lib/imo/students.json \
ADMIN_KEY=$(openssl rand -hex 16) \
ORIGIN=https://ваш-логин.github.io \
node server/server.js
```

Зависимостей нет, нужен только Node 18+. Поставьте перед ним обратный
прокси с HTTPS (nginx, Caddy) — браузер не пустит запросы с
`https://`-страницы на `http://`-сервер.

**Важно про бесплатные хостинги.** На free-тарифах Render и Railway диск
не сохраняется между перезапусками, а Render ещё и усыпляет сервис через
15 минут без запросов — список учеников обнулится. Этот вариант годится
для VPS с постоянным диском, не для бесплатного PaaS. Если хочется
бесплатно — берите вариант 1.

## Эндпоинты (одинаковые у обоих)

- `GET /api/board` — `{count, rows:[…]}`, публичный рейтинг без токенов.
- `POST /api/save` — тело `{token?, nick?, stats?, remove?}`; при первом
  вызове сервер выдаёт `token`, дальше клиент присылает его обратно.
- `GET /api/admin?key=…` — полный список по времени регистрации
  (работает, только если задан `ADMIN_KEY`).

Сколько учеников зарегистрировалось, видно тремя способами: в разделе
«Профиль» у владельца страницы, через `GET /api/admin` и напрямую в
хранилище (`npx wrangler d1 execute imo-rating --remote --command "SELECT
COUNT(*) FROM students"` или файл `DATA`).

## Честно о безопасности

Токен, который сервер выдаёт при регистрации, — одновременно и логин,
и пароль ученика; он лежит в `localStorage` браузера. Этого достаточно,
чтобы никто не переписал чужую строку, но это **не настоящая
аутентификация**:

- очистил браузер — потерял строку (придётся зарегистрироваться заново);
- общий компьютер — общий токен;
- показатели присылает клиент, поэтому ученик с консолью разработчика
  может отправить себе любые баллы. Сервер только ограничивает их сверху
  разумными значениями.

Для школьного рейтинга это нормально. Если нужен рейтинг, которому можно
доверять на отборе, оценки должен ставить не клиент, а проверяющий —
такого режима здесь нет.

Персональных данных ни один из вариантов не хранит: только имя, которое
ученик вписал сам, и числа.
